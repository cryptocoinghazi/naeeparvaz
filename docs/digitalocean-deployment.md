# Naee Parvaz deployment: DigitalOcean with GoDaddy DNS

This runbook deploys `https://naeeparvaz.com` as an Astro Node service on DigitalOcean App Platform. The domain registration, nameservers and DNS zone remain at GoDaddy.

The application does **not** require Cloudflare DNS, Workers, D1, Access or `cloudflared`. Cloudflare Turnstile is retained only as an independent verification service for the public contact form and admin sign-in.

Complete the sections in order. Never paste a real API key, database URL, session secret or local code into source files, screenshots, chat or GitHub.

## 0. Revoke the exposed Resend key

The Resend key visible in the earlier screenshot must be treated as compromised.

1. Sign in to [Resend API Keys](https://resend.com/api-keys).
2. Delete the exposed key.
3. Do not reuse it locally or in DigitalOcean.
4. Create the replacement only after `send.naeeparvaz.com` is verified in section 3.

## 1. Architecture and expected cost

```text
GoDaddy registration and authoritative DNS
                    |
                    v
DigitalOcean App Platform HTTPS service
                    |
                    +--> DigitalOcean Managed PostgreSQL
                    +--> Resend email API
                    +--> Turnstile Siteverify API
```

The checked-in [`.do/app.yaml`](../.do/app.yaml) attaches:

- one 512 MiB App Platform service; and
- one existing production PostgreSQL database named `naee-parvaz-db`.

The app is connected to the default Bangalore `blr1` VPC so `${database.DATABASE_PRIVATE_URL}` stays on DigitalOcean's private network. The VPC ID in the specification is a non-secret resource identifier for this DigitalOcean account.

Both are paid DigitalOcean resources. At the time of the first deployment they total approximately **$20.15/month** before taxes and overages ($5 App Platform plus $15.15 managed PostgreSQL), but always review the current [App Platform pricing](https://docs.digitalocean.com/products/app-platform/details/pricing/) and database price shown in the control panel before creating them. The specification does not deploy anything by itself.

DigitalOcean's official Node guidance uses a Git repository, build command, run command and runtime environment variables. Astro's official Node adapter produces the standalone server used here. See the [App specification reference](https://docs.digitalocean.com/products/app-platform/reference/app-spec/) and [Astro Node adapter](https://docs.astro.build/en/guides/integrations-guide/node/).

## 2. Production values

| Name | DigitalOcean storage | Secret? | Purpose |
| --- | --- | --- | --- |
| `DATABASE_URL` | Bindable runtime value `${database.DATABASE_PRIVATE_URL}` | Yes | Private PostgreSQL connection used by the website and migration runner. |
| `DATABASE_CA_CERT` | Bindable runtime value `${database.CA_CERT}` | Public certificate | Verifies the managed PostgreSQL server's TLS certificate. |
| `ADMIN_EMAIL` | Runtime variable | No | Must be exactly `editor@naeeparvaz.com`; no other address receives an editor code. |
| `SESSION_SECRET` | Encrypted runtime variable | Yes | HMAC key for login codes and privacy-preserving request identifiers. |
| `CONTACT_FROM_EMAIL` | Runtime variable | No | Fixed Resend sender: `website@send.naeeparvaz.com`. |
| `RESEND_API_KEY` | Encrypted runtime variable | Yes | Sends both contact messages and editor one-time codes. |
| `TURNSTILE_SITE_KEY` | Runtime variable | Public | Renders Turnstile on contact and editor login pages. |
| `TURNSTILE_SECRET_KEY` | Encrypted runtime variable | Yes | Verifies Turnstile tokens server-side. |
| `LOCAL_ADMIN_CODE` | Local `.env` only | Yes | Local browser code generated by `start-local.sh`; never add it to DigitalOcean. |

The app specification already contains the fixed public values and the PostgreSQL binding. You add the three production secrets and the Turnstile site key through the dashboard after the app exists.

## 3. Keep DNS at GoDaddy and verify Resend

### 3.1 Back up the existing DNS zone

1. Sign in to GoDaddy.
2. Open **My Products → Domains → naeeparvaz.com → DNS**.
3. Export the zone if available and take screenshots of every record.
4. Confirm the zone still contains:
   - all five Google Workspace MX records;
   - `google._domainkey` DKIM;
   - `_dmarc`;
   - Google site verification;
   - current apex website records;
   - the current `www` record; and
   - any other service or verification record.

Do not change nameservers. Do not delete or replace Google Workspace MX, DKIM or DMARC records. The website cutover later changes only the apex/`www` web records.

### 3.2 Verify the Resend subdomain

1. Open [Resend Domains](https://resend.com/domains).
2. Add exactly `send.naeeparvaz.com`.
3. Resend displays account-specific SPF, DKIM and return-path records.
4. In GoDaddy DNS, add every displayed record with the exact type, host, value and priority.
5. Do not copy sample DNS values from this guide.
6. Wait for Resend to report **Verified**.

Using the isolated sending subdomain prevents these records from replacing Google Workspace mail at the root domain. See [Resend domain verification](https://resend.com/docs/dashboard/domains/introduction).

### 3.3 Create the replacement key

1. Open **Resend → API Keys → Create API Key**.
2. Name it `naee-parvaz-production`.
3. Select **Sending access**.
4. Restrict it to `send.naeeparvaz.com`.
5. Copy it once into a password manager.

The key becomes `RESEND_API_KEY`. It is used only by the server and must be encrypted in DigitalOcean. See [Resend API-key permissions](https://resend.com/docs/dashboard/api-keys/introduction).

## 4. Create Turnstile keys

Turnstile works even though GoDaddy hosts DNS and DigitalOcean hosts the website. It does not require a Cloudflare proxy or tunnel.

1. Open the [Cloudflare Turnstile dashboard](https://dash.cloudflare.com/?to=/:account/turnstile).
2. Create a Managed widget named `Naee Parvaz Website Forms`.
3. Add `naeeparvaz.com` as an allowed hostname.
4. Copy the site key into a password manager entry named `TURNSTILE_SITE_KEY`.
5. Copy the secret into `TURNSTILE_SECRET_KEY`.

After DigitalOcean creates the app, temporarily add its exact generated `*.ondigitalocean.app` hostname to this widget so the preview tests in section 7 work. Remove that preview hostname after the production DNS cutover is complete.

The public site key renders the widgets. The server-only secret is sent to Siteverify for the `contact` and `admin-login` actions. See [Turnstile setup](https://developers.cloudflare.com/turnstile/get-started/).

For local development, the repository template uses Cloudflare's published dummy pair. Never use it in production. See [Turnstile test keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

## 5. Create the DigitalOcean database and app

The browser's generic **Create App** wizard may infer a Node service without loading `.do/app.yaml`. If its review screen shows two containers, no database, no environment variables or an unexpected price, stop and do not click **Create App**. Use the checked-in specification through `doctl` as described below.

1. Sign in to [DigitalOcean](https://cloud.digitalocean.com/).
2. Open **Apps → Create App**, choose **GitHub**, and authorize DigitalOcean to access only `cryptocoinghazi/naeeparvaz`. You may leave the wizard after the repository connection is established.
3. Create one production PostgreSQL 18 cluster named exactly `naee-parvaz-db` in Bangalore (`blr1`) with one `db-s-1vcpu-1gb` node. Keep it on the default `blr1` VPC and review the displayed recurring database price before confirming.
4. In the cluster's **Users & Databases** page, add a database named exactly `naee_parvaz`. The app leaves `db_user` unset so DigitalOcean selects the managed database's default binding; its password is injected through the bindable URL and is never copied into the repository.
5. Install and authenticate the current [DigitalOcean CLI](https://docs.digitalocean.com/reference/doctl/how-to/install/) with a short-lived token that has only the account, app and database permissions needed for setup.
6. Validate the app specification from the repository root:

   ```bash
   doctl apps spec validate .do/app.yaml
   ```

7. Review the validated region, VPC, service size, database binding, environment variables and total recurring price.
8. Create the app:

   ```bash
   doctl apps create --spec .do/app.yaml
   ```

9. Revoke the temporary CLI token after setup is complete. GitHub automatic deployment remains enabled for future pushes to `main`.

The specification binds `DATABASE_URL` to `${database.DATABASE_PRIVATE_URL}` and `DATABASE_CA_CERT` to `${database.CA_CERT}`. DigitalOcean injects the actual private connection string and CA certificate at runtime; no database password is committed, and TLS verification remains enabled. The checked-in `vpc.id` must match the database cluster's `blr1` VPC. See [App Platform VPC setup](https://docs.digitalocean.com/products/app-platform/how-to/enable-vpc/) and [database bindable variables](https://docs.digitalocean.com/products/app-platform/how-to/use-environment-variables/).

The production start command applies every unapplied file in `db/migrations/` under a PostgreSQL advisory lock, then starts `dist/server/entry.mjs` on the App Platform-provided port.

Migration `002_import_existing_editor_content.sql` carries forward the two published videos and social profile URLs that were already saved in the former local D1 editor. It contains public editorial data only; no credential or contact-form message is migrated.

## 6. Add DigitalOcean variables and secrets

After the app exists, open **Apps → naee-parvaz → Settings → web → Environment Variables**.

Confirm these general runtime values from `.do/app.yaml`:

```dotenv
ADMIN_EMAIL=editor@naeeparvaz.com
CONTACT_FROM_EMAIL=website@send.naeeparvaz.com
HOST=0.0.0.0
NODE_ENV=production
```

Confirm `DATABASE_URL` displays as the bindable database value, not a copied literal password.
Confirm `DATABASE_CA_CERT` displays as the bindable CA certificate value.

Generate the authentication secret locally:

```bash
openssl rand -hex 32
```

Add the following in the dashboard and enable **Encrypt** for each secret value:

| Key | Value source | Encrypt? |
| --- | --- | --- |
| `SESSION_SECRET` | Output of `openssl rand -hex 32` | Yes |
| `RESEND_API_KEY` | Replacement sending-only Resend key | Yes |
| `TURNSTILE_SECRET_KEY` | Production Turnstile secret | Yes |
| `TURNSTILE_SITE_KEY` | Production Turnstile site key | No |

Do not add `LOCAL_ADMIN_CODE`. Save the variables and allow DigitalOcean to redeploy. DigitalOcean documents encrypted variables at [App Platform environment variables](https://docs.digitalocean.com/products/app-platform/how-to/use-environment-variables/).

## 7. Test the DigitalOcean preview before changing DNS

Use the generated `*.ondigitalocean.app` address first.

1. Confirm `/api/health/` returns JSON with `"status":"ok"`.
2. Open `/en/`, `/hi/`, `/en/contact/` and `/en/videos/`.
3. Submit one contact message and confirm it reaches `editor@naeeparvaz.com`.
4. Open `/editor/` in a private window.
5. Request a code using `editor@naeeparvaz.com` and confirm Resend delivers it.
6. Confirm the code signs in and the editor can save a draft video.
7. Sign out and confirm `/api/editor/settings/` returns `401` without a session.
8. Try another email address and confirm it receives no code.

The login response is deliberately generic, challenges expire after ten minutes, only five code attempts are allowed and sign-in requests are rate-limited using App Platform's `do-connecting-ip` header. DigitalOcean documents that header in [client IP addresses on App Platform](https://docs.digitalocean.com/support/where-can-i-find-the-client-ip-address-of-a-request-connecting-to-my-app/).

## 8. Connect the domain without moving DNS

1. In DigitalOcean open **Apps → naee-parvaz → Networking → Domains → Add Domain**.
2. Enter `naeeparvaz.com`.
3. Choose **You manage your domain**.
4. DigitalOcean displays the exact CNAME alias or apex A records required for this app. Copy them; do not use addresses from another tutorial.
5. Add `www.naeeparvaz.com` as a second domain/alias in DigitalOcean.
6. Return to GoDaddy DNS.
7. Replace only the old apex website A records with the A records shown by DigitalOcean. If GoDaddy offers supported root CNAME flattening, the DigitalOcean alias may be used instead.
8. Replace only the old `www` record with the CNAME shown by DigitalOcean.
9. Leave nameservers, Google MX, DKIM, DMARC, Google verification and Resend subdomain records unchanged.
10. Wait for DigitalOcean to confirm DNS and issue TLS certificates.

DigitalOcean documents the self-managed DNS option and apex A-record fallback at [Manage App Platform domains](https://docs.digitalocean.com/products/app-platform/how-to/manage-domains/). DNS propagation can take time. The application permanently redirects `www.naeeparvaz.com` to the canonical apex domain while preserving the path and query string.

- [ ] `/api/editor/*` returns `401` without a session.

- [ ] The exposed screenshot key has been deleted in Resend.
- [ ] `.env` is ignored and not committed.
- [ ] No real `re_` key, database URL, session secret, Turnstile secret or local code appears in tracked files.
- [ ] These checks pass before every deployment:

```bash

```

Review likely secret patterns without printing their values:

```bash
rg -l 're_[A-Za-z0-9_]{20,}|SESSION_SECRET=.+|LOCAL_ADMIN_CODE=.+|TURNSTILE_SECRET_KEY=.+' --glob '!node_modules/**' --glob '!dist/**' --glob '!.env'
```

## 10. Local development

Run `./start-local.sh`. It creates an ignored `.env`, starts PostgreSQL with Docker Compose, applies migrations and prints the local editor code.

Production email OTP is intentionally replaced locally by `LOCAL_ADMIN_CODE`; the application accepts it only in Astro development on `localhost` or `127.0.0.1`. Production builds ignore that variable even if it is accidentally configured.

Useful commands:

```bash
docker compose ps
docker compose logs database
docker compose down
npm run db:migrate
```

Do not run `docker compose down --volumes` unless erasing all local settings and video records is intentional.
